# How do you feel about working on products used by a large number of real users?

The number of users doesn't change how strict I am about code quality. My goal is to minimise risk and maximise stability regardless of audience size — scale changes the operational stress on the system, which means you design and test against that reality from the start. It's not a different standard, it's the same standard applied to different failure modes.

My bias is toward code that's easy to test, backed by automated tests that run every time the code changes. I've learned the hard way that mentally "clearing" something you tested earlier is a risk — a later change can interact with code you already moved past, and if you're not running a suite you won't catch it until it's someone else's problem. Reliable automated tests turn that assumption into something you can actually verify.
