# How did you balance frontend and backend work?

I let project needs drive the balance rather than enforcing artificial boundaries. On the Integrations Dashboard (July-November 2022), I was the sole frontend developer and learned backend implementation (API endpoints, PostgreSQL) under senior mentorship. On Nexus Dashboard (Oct 2025-Feb 2026), I was the technical lead focusing on frontend architecture while collaborating with a backend engineer for integration.

My strength is frontend with full-stack capability. I think in terms of complete features, not just UI or API layers. When building the Integrations Dashboard, I designed the database schema and API endpoints based on what the frontend actually needed, not what seemed theoretically complete. This end-to-end thinking prevents mismatches between frontend expectations and backend implementation.

The balance shifts based on team composition. When working with dedicated backend engineers, I focus on frontend architecture and integration while they handle backend complexity. When working solo or on small teams, I handle full-stack. This flexibility means I can contribute where needed rather than waiting for "my part" to become available.

At Nurtur, I was primarily responsible for React/TypeScript development but built backend API endpoints when needed, collaborated closely with backend engineers on system integration, and reviewed backend code when helping mentor developers. The mentoring aspect meant teaching frontend concepts to backend developers - bridging that frontend/backend divide rather than reinforcing it.

Full-stack capability doesn't mean equal split - it means understanding both sides well enough to build complete, integrated features that work.
