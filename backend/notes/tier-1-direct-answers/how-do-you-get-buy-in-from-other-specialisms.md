# How do you get buy-in from specialists in other fields?

On Nexus I had to convince stakeholders that the way I was building the foundation was worth it. Solid structural work produces almost no visible early progress — which can look like being slow. I explained what I was actually doing: modular components so dashboard features would be swappable without rewriting each other, a system for handling API calls to prevent race conditions and maintain a single source of truth. The value wouldn't be obvious until nothing was breaking six months later.

The key was aligned interests. Nobody wanted a product that cracked apart in a year. I wasn't fighting opposing incentives — the hard part was explaining the perspective, not overcoming a genuine disagreement. Once they understood that building it right made it easier to work on over time, not harder, the conversation was easy.

For cases where someone doesn't understand why something matters: my fallback is a minimal version that demonstrates value rather than argues for it theoretically. If they agree to a small version and it starts showing value, the reasoning lands in a much more visceral way than any explanation. I honestly haven't had to use this often — if I thought something mattered and had a clear reason, people would usually let me run with it.
