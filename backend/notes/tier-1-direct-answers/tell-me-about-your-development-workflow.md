# Tell me about your development workflow

I've been using Git professionally since 2020, working in teams of 3-20 developers at Nurtur and on solo projects deployed to production. At Nurtur, we used Azure DevOps for version control and CI/CD. For personal projects like WhatNow and moh-ami, I use GitHub with Railway or Render - pushing to main triggers automatic builds and deployments.

For a typical feature, I create a branch from main, implement with React/TypeScript, write tests for critical components, and do manual testing before creating a pull request. Code review is central to my workflow. I review teammates' pull requests and provide educational feedback - not just approving or rejecting, but explaining why patterns work. When my code is reviewed, I incorporate feedback professionally and use it as a learning opportunity.

My daily workflow at Nurtur involved standups twice a week, then most of my day writing React/TypeScript code. I'd review teammates' PRs, mentor backend developers learning frontend, test before submitting my own PRs, and document complex systems like the Nexus Dashboard foundation blocks architecture. Writing code was the core, but collaboration through reviews, mentoring, and cross-team communication with backend engineers and designers was equally important.

Git provides safety nets for experimentation. Commit messages document decision-making. Pull requests capture discussion and context. The workflow ensures quality through review and testing before merge.
