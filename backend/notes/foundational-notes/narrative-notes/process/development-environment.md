# Development Environment

## Primary Tools

**IDE**: I use Cursor as my primary development environment. It's what I write code in and where I spend most of my development time.

**Browser**: Google Chrome is my main browser for both general use and local development. I use Chrome's developer tools extensively for debugging, inspecting network requests, testing responsive layouts, and profiling performance.

**Operating System**: Windows (the workspace context shows I'm using Windows 10).

## The Sandbox Approach

I like having a sandbox project to test out ideas in an isolated environment. This allows for more rapid prototyping of unusual ideas without risking or working around existing code.

When I have a concept I want to explore - a new pattern, an unfamiliar library, or an experimental approach - I can try it in the sandbox first. If it works, I can bring the approach into the real project with confidence. If it doesn't work, I've learned something without complicating the main codebase.

This separation between "exploration space" and "production code" means I can be more experimental and take more risks without jeopardizing working systems. The sandbox is where I can break things freely.

## Why This Setup Works

**Cursor** provides the AI assistance and development features I need for modern development workflows. The AI capabilities help with code generation, refactoring, and problem-solving without leaving the editor.

**Chrome** has the developer tools I rely on daily. The ability to inspect elements, debug JavaScript, monitor network traffic, and test responsive behavior makes it essential for web development.

**Sandbox projects** mean I'm never blocked by "I don't know if this will work." I can test ideas quickly in isolation, learn from them, and bring proven approaches into production code. This makes me more willing to try new approaches because the cost of experimentation is low.

## What This Environment Supports

This setup supports my development style:

- **Rapid iteration**: Test ideas quickly in the sandbox, bring working concepts to production
- **AI-assisted development**: Cursor's AI features accelerate common tasks
- **Full-stack development**: All tools work equally well for frontend and backend work
- **Debugging and inspection**: Chrome DevTools for understanding what's happening at runtime
- **Isolation between experiments and production**: Keep exploration separate from shipping code

The environment is simple - IDE, browser, sandbox - but it covers everything I need for building production web applications while maintaining space for experimentation and learning.
